# 栖隼 BF 微架构

以下以本仓库的 BF 冻结 RTL 为准。BF 实现 LA32R 整数与特权指令，每拍最多分派和退休两条，设有三条执行通道。 [顶层接口](../myCPU/mycpu_top.v)

## 1. 整体流水线和寄存器边界

取指、执行和退休各有自己的可停顿边界。取指请求队列隔开分支预测和 I-cache 反压，指令 FIFO 吸收缓存行返回的突发宽度，ROB 则允许执行次序和退休次序不同。下图的方括号表示跨周期保存的寄存器、队列或表项。

```text
[取指 PC] → 预测 / 地址转换 → [取指请求队列]
          → I-cache 查找 → [八项指令 FIFO] → 译码 → [双槽译码寄存器]
          → 重命名 → [16 项 ROB / 操作数 / 寄存器映射]
                           │
                           ├─ 就绪选择 → [X / Y 执行寄存器] → ALU、分支、乘除
                           └─ 就绪选择 → [M 执行寄存器] → [AGU / 暂存槽] → TLB、D-cache
                                                                            ↕
                                                                    [四项 store queue]

          [执行结果] → 按标签写回 [ROB] → 按序退休 → [架构寄存器]
                                            ├─ 授权 store 排出
                                            └─ 分支训练 / 异常 / 重取 → [取指 PC]
```

下表是一条普通整数 ALU 指令的最早时序。假设取指走快路且命中，队列有空位，操作数就绪，指令完成后成为可退休的队首。表中的阶段表示每拍的工作和拍末保存的状态。

| 拍 | 阶段 | 拍末写入 |
| --- | --- | --- |
| 1 | F1，预测并取得取指地址 | 取指请求队列 |
| 2 | F2，I-cache 接受请求并读标签与数据 | Cache 查找寄存器、前端在途请求元数据 |
| 3 | F3，I-cache 命中并选择返回指令 | 八项指令 FIFO |
| 4 | D，选择最多两条并译码 | 双槽译码寄存器 |
| 5 | R，重命名并按程序顺序分派 | ROB 项、源操作数和最新写者映射 |
| 6 | Q，从就绪项中为各端口选择指令 | X 或 Y 执行寄存器 |
| 7 | X，执行运算 | ALU 结果寄存器 |
| 8 | W，按生产者标签回写并唤醒依赖项 | ROB 结果、完成位等状态 |
| 9 | C，按程序顺序退休 | 架构寄存器、ROB 队首 |

第 8 拍可同时用已寄存的 ALU 结果旁路给另一条指令。直接分支另有直写 ROB 的路径，访存和乘除各有自己的多拍路径。取指缺失、操作数依赖、执行端口冲突或队首等待都会增加实际周期。 [模块连线](../myCPU/ooo_core.sv) · [后端 RTL](../myCPU/ooo_backend.sv)

## 2. 取指与分支预测

### 2.1 预测器 `ooo_predict`

预测粒度是一条 16 B 取指缓存行。行内四个指令位置分别对应四个预测 bank，由 `PC[3:2]` 选择。每个 bank 有 256 项 BTB、1,024 项两位全局方向计数器，以及按分支位置索引的两位本地方向与择向计数器。BTB 通过行索引和高位地址标签找到已记录的分支类型和目标。条件分支用 12 位历史做折叠 gshare，将 `PC[13:4]` 与历史低 10 位及折叠后的高两位异或，择向计数器决定采用全局还是本地方向。前端保留行内从当前 PC 到第一个预测跳转之间的指令，随后用该分支目标产生下一请求。

调用和返回还有八项 RAS。前端接受预测时更新推测历史及返回栈，退休反馈更新已提交的状态。错误路径被冲刷时，预测器恢复成已提交的方向历史和返回栈状态。预测时的 PHT 索引随指令进入 ROB，退休时用原索引训练，避免重新按当前历史计算出另一个位置。 [预测器 RTL](../myCPU/ooo_predict.sv)

### 2.2 前端 `ooo_frontend` 与译码 `ooo_decode_pipe`

- **生成请求。** 前端维护当前 PC 和两项取指请求队列 `request0/1`。普通分页还保留一项 4 KiB 页的地址转换，供同页后续取指复用。重定向清理旧请求，条件允许时新请求可以旁路队列。
- **跟踪在途请求。** I-cache 接收后，前端用寄存器记住该请求的 PC、有效指令数、预测下一 PC 和训练信息，等缓存数据返回再合成指令包。重定向或串行取指维护期间，旧路径的返回会被丢弃。不可缓存取指一次读取一个 32 位字。
- **缓冲和译码。** 指令 FIFO 共八项、四个 bank，按行内槽位最多写入四项，每拍可取出两项。取指故障也占一项，携带故障 PC 和异常信息，由后端在队首处理。`ooo_decode_pipe` 保存两个已译码槽，对直接分支预先算目标及与预测的匹配状态，并向分派端提供稳定的操作类型和寄存器编号。`ooo_pkg` 集中定义跨模块记录、译码、整数运算和加载扩展函数。 [前端 RTL](../myCPU/ooo_frontend.sv) · [译码 RTL](../myCPU/ooo_decode_pipe.sv) · [类型和函数](../myCPU/ooo_pkg.sv)

## 3. 乱序后端 `ooo_backend`

### 3.1 ROB 和寄存器重命名

16 项 ROB 同时记录在途指令及其等待发射所需的操作数。`head`、`tail` 和 `used` 管理循环队列。每项用占用、已发射和已完成状态表示阶段，随项保存 PC、预测、异常、目标寄存器和结果。4 位 ROB 索引就是生产者标签，释放在退休或冲刷时发生。

每个架构寄存器分别维护已退休值以及最新推测写者。分派读源数时，若最新写者还没完成，就记其标签并等待唤醒。若值已就绪，直接从按架构寄存器寻址的推测值表取值，省去以标签二次索引 ROB 结果的路径。如果双分派中的第二条读第一条刚分配的目的寄存器，分派绕过旧映射，直接绑定第一条的新标签。对零寄存器的读取始终得到零。

### 3.2 执行选择、快速唤醒与回放

X 与 Y 各自选择本端口的最老就绪项。普通整数运算可以分到两路，分支和乘除走 X。M 单独看最老的尚未发射访存项，只有它就绪才继续，因此后续内存操作不会越过它提前算地址。独立端口可在同一拍处理三项积压的指令，双分派和双退休将持续的架构指令吞吐上限限制为每拍两条。

ALU 可以在发射时公布标签，消费者据此准备旁路。D-cache 接受缓存 load 时也发送 `load_hint`，预测它会按命中时序返回。消费者真正执行前检查返回值、标签和故障状态。缺失或异常使预期旁路不可用，后端撤销消费者的本次发射，保留 ROB 项供重发，并阻止这次尝试产生执行副作用。正常回写用生产者标签唤醒依赖项。在后端里可以沿 `src_a/src_b`、发射寄存器和 `registered_x/y` 追踪一次数据依赖。

例如，先遇到 `ld.w r5, r6, 0`，随后是依赖 `r5` 的 `add.w r7, r5, r8` 和独立的 `xor r9, r10, r11`。Load 缺失时，add 会等待或回放，xor 可以先完成并暂存于 ROB。退休仍依次处理 load、add、xor。如果 load 发生异常，后两条的推测结果随冲刷丢弃。

### 3.3 分支、双退休和精确异常

直接分支的目标与顺序下一 PC 已在译码保存，执行只需写回实际方向及预测是否失配。`JIRL` 的目标依赖寄存器，先保存计算出的目标，再与预测值比较。到退休时才训练预测器，并在预测错误时把前端重定向到实际的下一 PC。

第一条正常退休后，第二条需要已完成、分支已解析且无异常。队首误预测或执行的是串行指令时，仅退休队首。两个 store 同拍只提交一个，预测器每拍也只接收一次退休训练。退休写架构寄存器并给 store 队列提交授权。异常在队首生效，中断在已提交存储排空且没有进行中的串行指令或设备读时进入。冲刷清掉年轻 ROB 项和推测映射，保留已退休的架构状态及已提交的 store。 [后端 RTL](../myCPU/ooo_backend.sv)

## 4. 访存与一级缓存

### 4.1 LSU `ooo_memory`

M 通道输出地址生成结果，LSU 用 AGU 槽和暂存槽衔接地址转换、store queue 与 D-cache。常规访存通过数据侧 TLB 取得物理地址和缓存属性。对齐的缓存 load 在队列空闲、没有旧 store 与串行操作、地址可由直映或 DMW 快速得到等条件满足时，可以直接进入 D-cache 查找。跨出可安全判断的段、需要 TLB 翻译或存在旧 store 时，走常规路径。

四项 store queue 用四个边界表示 store 走到哪里。指针带回绕信息，冲刷能保留已提交记录，连同冲刷当拍获准提交的 store。

| 队列范围 | 含义 |
| --- | --- |
| `sq_pop … sq_issue` | D-cache 已接受，等待完成响应 |
| `sq_issue … sq_commit` | 已退休授权，等待向 D-cache 发请求 |
| `sq_commit … sq_push` | 已记录地址和数据，等待对应 ROB 项退休 |

普通 store 可以在排入队列后标记 ROB 项完成，但要等退休授权才会写入缓存或设备。Load 检查较老 store 的物理字地址与字节掩码，每个字节选择覆盖它的最新一笔 store。请求的字节都能转发时直接返回。只有一部分匹配时先等待旧 store 排出，然后再读缓存。例如 `st.b p` 后的 `ld.w p` 需要四个字节，单条字节 store 只能覆盖其中一个。不可缓存访问受额外的顺序限制，设备读必须等到 ROB 队首且旧提交 store 已排空。

D-cache 端口有反压时，`queued_request` 可以保存一笔请求。缓存 load 在存在待排出 store 时可有界优先，最多连续让三次。队列占到三项时优先排 store。串行引擎的缓存请求拥有单独的仲裁入口。错误路径 load 的迟到数据可以被接收并丢弃，只有仍记录为有效的 load 才能写回 ROB。 [LSU RTL](../myCPU/ooo_memory.sv)

### 4.2 D-cache `ooo_dcache`

BF 使用 16 KiB、两路、128 组、64 B 行的 D-cache。物理地址 `PA[12:6]` 选组，`PA[31:13]` 为标签，`PA[5:2]` 选行内字。每路的数据按字索引低位分成四个 bank。接受请求时寄存两路标签和脏位，并发起数据 RAM 读取。命中后选路并取字，store 根据字节使能更新数据和脏位。

缺失时优先选择无效路。若被替换的行是脏行，分四次从四个 bank 并行读取整行，发 16 个 32 位写拍并等写响应，然后发 16 拍读回填。Store 缺失按写分配处理，将写掩码合并进回填数据。对于 load，请求的目标字一到就可提前返回给后端，缓存继续收完整行，回填成功才安装有效标签。不可缓存访问通过 AXI 发单拍请求，按访问宽度及写掩码操作。

缓存维护复用标签查找和写回状态机。索引模式选定组与路，命中模式先比物理标签。需要清理的脏行沿写回路径排出后再失效。`early_load`、`lookup_tag` 和 `COLLECT → WRITE_ADDRESS → WRITE_RESPONSE → READ_ADDRESS → REFILL` 是阅读命中、写回与回填时的主要入口。 [D-cache RTL](../myCPU/ooo_dcache.sv)

### 4.3 I-cache `ooo_icache`

I-cache 为 8 KiB、两路、256 组、16 B 行，按物理地址索引和比较标签。命中时对齐返回一整行。普通缺失发 4 拍读请求。顺序取指允许预取时，可合并成 8 拍 burst 取当前行和下一行，并在 4 KiB 页边界约束这个合并。需求行收齐后可以先返回，预取行暂存在独立缓冲，等真正命中该缓冲再进入组相联缓存。单个不可缓存取指发一拍读。

重定向时，尚未交给 AXI 的旧查找可以取消。已经在途的事务继续收尾，由前端排除旧路径响应。维护操作要等 I-cache 回到可接收失效请求的状态，同时清除预取缓冲，防止下一次取指使用旧预取数据。 [I-cache RTL](../myCPU/ooo_icache.sv)

## 5. 特权、地址转换和串行指令

### 5.1 地址转换与架构状态 `ooo_priv`

取指端与数据端各有寄存后的转换结果。`CRMD` 的 DA/PG 控制直接地址与分页模式。分页时先检查直接映射窗口 DMW，对窗口允许的特权级按 VSEG/PSEG 做段转换并携带 MAT 缓存属性。其余地址由 16 项全相联 TLB 匹配虚页号、ASID 或全局位。每项对应一对奇偶页，支持 4 KiB 和 2 MiB 页，并在选中半页后检查有效位、权限及写入时的脏位。

CSR 和 TLB 的架构更新在串行指令退休时进行。TLB 查找、读写、填充和失效均由相应指令控制，填充使用循环变化的索引。异常入口保存返回地址与原特权状态，设置异常编码，相关地址异常记录到 `BADV`。TLB 重填异常选择单独入口，`ERTN` 从保存状态恢复并重定向。定时器、软件中断和同步后的外部中断综合为待处理中断，经屏蔽和总使能后由后端在指令边界接收。

LL/SC 由特权模块维护一份以物理字地址为粒度的保留。LL 成功退休后建立保留，SC 根据匹配结果决定是否发写请求并返回成功位。SC 退休和同一保留缓存行上的普通 store 提交会清除保留。`ERTN` 按 `LLBCTL.KLO` 控制是否保留。 [特权模块 RTL](../myCPU/ooo_priv.sv)

### 5.2 串行执行引擎 `ooo_serial`

系统类指令在 ROB 队首、源数就绪、已提交存储排空后启动。`ooo_serial` 依次保存操作数、计算地址、按需要等数据侧翻译、检查特权或对齐条件，再发起缓存访问或返回结果。`CACOP` 指定目标缓存及维护方式，命中类维护先查地址转换。LL/SC 复用缓存接口。`DBAR` 在队首等旧操作及已提交的 store 完成，再让后续访存继续。异常或系统操作引起的重取统一经后端重定向。

### 5.3 BF 的 IBAR 与缓存枚举

BF 的 `IBAR` 在 ROB 队首串行执行，从下一条 PC 恢复取指。通过 `IBAR` 单独发布新指令时，脏数据可能留在 D-cache，I-cache 也可能保留旧指令。后续 Linux 修复版在重取前增加全 D-cache 写回失效和全 I-cache 失效。

BF 的 D-cache 实际有 128 组。`CPUCFG(0x12)` 仍返回 64 组的编码 `0x0606_0001`。实板基准的启动段用 128 组遍历缓存，后续修复版更新了 CPUCFG 枚举。 [BF 串行引擎](../myCPU/ooo_serial.sv) · [退休重取](../myCPU/ooo_backend.sv) · [缓存枚举](../myCPU/ooo_priv.sv)

## 6. 乘除、总线和监控

| 模块 | 实现要点 |
| --- | --- |
| [`ooo_mdu`](../myCPU/ooo_mdu.sv) | 乘法把输入拆为 16 位半字，生成四个部分积，再分级合并并处理有符号高字。除法用逐位迭代，每轮处理一位，最后对商和余数恢复符号。结果都带 ROB 标签回写。 |
| [`ooo_axi`](../myCPU/ooo_axi.sv) | 仲裁 I-cache 和 D-cache 的读请求，分别用 ID 0 和 1，按返回 RID 分发。两侧各可有一笔读在途。D-cache 写通道单独跟踪地址、数据与响应，AW 和 W 各自承受反压。 |
| [`mycpu_top`](../myCPU/mycpu_top.v) 与 [`ooo_core`](../myCPU/ooo_core.sv) | 顶层提供比赛 SoC 兼容的 AXI 和调试端口。Core 实例化各模块并连接转换、发射、回写和退休信号。板级适配生成 `core_top`，之后依次进入 AXI3/AXI4 桥、跨时钟桥与 SoC 互连。 |
| [`ooo_perf`](../myCPU/ooo_perf.sv) 与板级监控 | 收集两槽退休、周期、分支与缓存等事件，经 VIO 读取。若两个退休槽在同拍触及计时边界，按槽 0、槽 1 的程序顺序计算 ROI 增量。 |
